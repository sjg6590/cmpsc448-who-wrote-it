\section{Problem}
\label{sec:problem}

The question in this project is simple. Given text that a language model wrote, can I tell which model wrote it?

I treat this as supervised learning, the way Chapter 1 sets it up. Each example is a pair $(x, y)$. The gold label $y$ is the model name. The input $x$ is some text: the response, the user's instruction, or both. I want a function $f(x)$ that predicts $y$.

There are four labels, so a guess would be right about one time in four. Accuracy of 0.25 is the chance line. The four models are balanced, so that number is fair.

I looked at four questions:

\begin{itemize}
\item \textbf{RQ1.} If $x$ is only the response, how well can a CNN and an LSTM name the model?
\item \textbf{RQ2.} Does the user's instruction help? I compare the instruction alone, the response alone, and the two concatenated. Chapter 7 trains instruction-tuned models on a concatenated (instruction, input) pair. I used the same idea, with the response in the input slot.
\item \textbf{RQ3.} If I train on some tasks and test on a task I left out, does the score drop? Chapter 6 talks about a source task $S$ and a target task $T$, and says labeled data from $S$ may not adapt well to a new domain. Chapter 7 says the instructions at train time and test time should match.
\item \textbf{RQ4.} What makes the responses look different? Chapter 7 (instruction tuning) and Chapter 8 (RLHF) are the course explanation for why models pick up different habits. I measure those habits and then delete some of them and retrain.
\end{itemize}

Every number below comes from one run with seed 42. The file is \texttt{results/metrics.json}.

\section{Dataset}
\label{sec:data}

\subsection{Where the text came from}

I used UltraFeedback \cite{cui2023ultrafeedback}, the public set at \href{https://huggingface.co/datasets/openbmb/UltraFeedback}{\texttt{openbmb/UltraFeedback}}. The license is MIT. I did not call any model API, and I did not use my own chats.

UltraFeedback took prompts from ShareGPT, UltraChat, Evol-Instruct, TruthfulQA, FalseQA, and FLAN. For each prompt it asked four models from a larger pool to answer. I kept one model from each of four families:

\begin{center}
\begin{tabular}{lll}
\toprule
Label & Family & Who trained it \\
\midrule
\texttt{bard} & Bard & Google \\
\texttt{falcon-40b-instruct} & Falcon & Technology Innovation Institute \\
\texttt{gpt-4} & GPT & OpenAI \\
\texttt{llama-2-70b-chat} & Llama & Meta \\
\bottomrule
\end{tabular}
\end{center}

I left out WizardLM, Vicuna, and UltraLM because those are Llama models with extra training. I wanted the family itself to be different. I left out StarChat because it is a code model, so a code prompt would almost give the label away.

I dropped responses shorter than 40 characters, responses that were not text, and responses that were mostly not Latin letters. I dropped instructions shorter than 12 characters. The released files do not include the \texttt{id} field from the dataset card, so I hashed the instruction and used that as the prompt id.

\subsection{A hole I had to close}

Bard has no answers on three FLAN subsets: \texttt{flan\_v2\_niv2}, \texttt{flan\_v2\_p3}, and \texttt{flan\_v2\_flan2021}. That is 17,939 prompts. Those prompts use a very fixed template. If I had kept them, two things would go wrong. The instruction alone could rule out Bard. The responses would also look different, because those templates ask for short answers and Bard never wrote them. That is not a writing style. It is a missing row in the table. I dropped those sources. On the sources I kept, all four models were actually queried.

\subsection{Task labels}

RQ3 needs a task. UltraFeedback does not give one, so I labeled each instruction with rules in \texttt{src/domains.py}. The label does not look at the response. I check code first, then writing, then reasoning, then question answering. I dropped prompts that matched none of these (9,681 prompts).

\begin{itemize}
\item \textbf{Code.} A code fence, a language name, or a phrase like ``write a function.'' I did not use the word ``function'' by itself. It shows up in normal sentences.
\item \textbf{Writing.} A request for a story, poem, essay, email, article, letter, speech, or summary.
\item \textbf{Reasoning.} What is left of \texttt{flan\_v2\_cot}: entailment items, multiple choice, and step-by-step word problems. A clean ``math only'' bucket was too small once I stopped matching the word ``proof'' in ordinary sentences.
\item \textbf{QA.} TruthfulQA, FalseQA, and remaining questions.
\end{itemize}

These rules are rough. A summary is not the same kind of writing as a short story. I froze the rules before I looked at test scores.

\subsection{Balance and the split}

Question answering was much larger than writing. Inside each task I kept the same number of rows for each model, and I capped that number at 700. The cell sizes are code 676, QA 700, reasoning 664, and writing 627 per model. That is 10,668 rows and 8,948 prompts.

Chapter 1 splits with \texttt{train\_test\_split} and a 20\% test set. I also needed a validation set, because Chapter 9 says to look at the validation curve when you choose training settings. I used 70\% train, 15\% validation, and 15\% test. The split is by prompt, and it is stratified by task. Every answer to one prompt stays in one split. No prompt id is in two splits. The counts are a little uneven across models because one prompt was not always answered by all four models.

\section{Models and training}
\label{sec:models}

Both neural models are many-to-one classifiers, like the sentiment example in Chapter 4. A sequence of word vectors goes in. One label comes out. The scores go through a softmax, and the loss is negative log-likelihood, as in Chapter 9. In PyTorch that is \texttt{CrossEntropyLoss}. The optimizer is Adam, which Chapter 9 calls the usual choice. The learning rate is $\alpha = 10^{-3}$. The batch size is $|B| = 64$. Chapter 9 says a batch size is often a power of two and somewhere between 1 and a few hundred. I did not do a batch-size search. The validation curve for the CNN rose and then flattened, so I left $|B|$ alone.

I did not use dropout or weight decay. We did not cover those. I also did not clip gradients. On one ablation the CNN loss blew up anyway. I say more about that in the lessons.

\subsection{Words and vectors}

I split text into words and punctuation and then lowercase it. Chapter 6 says each word gets one vector. I learned that table while training. The vocabulary is the 12,000 most common training words that appear at least twice, plus a pad token, an unknown token, and a separator. Validation and test words that were not in training become unknown. I did not load GloVe or word2vec. Those are the static embeddings from Chapter 6, one vector per word for every context. Mine is the same kind of table, but it is learned on this dataset.

Sequences are cut at 128 tokens. For the concatenated view I keep at most 40 tokens of the instruction and 87 tokens of the response, with a separator in between. If I had cut the raw concatenation at 128, a long instruction would have deleted the response.

\subsection{CNN}

Chapter 4 builds a CNN as convolution, then ReLU, then max-pooling, then a fully connected layer. The 1D example uses a width-3 filter and zero padding on both ends. I did that. The input to the convolution is the sequence of 128-dimensional word vectors. I use 96 filters, so there are 96 activation maps. Each map is a channel, which the lecture calls one version of the representation. After ReLU I take the max over time. That is the ``most representative'' feature from the pooling slides. A linear layer turns the 96 numbers into 4 scores.

The lecture's CNN-versus-RNN slide says a CNN is fast, sees left and right context, and only sees local context. That is the model I report as the CNN.

I also tried filter widths 3, 4, and 5 together, on the output-only task only. Chapter 4 never discusses more than one width. I found that setup outside of class. It is an extra comparison, not the main CNN.

\subsection{LSTM}

The required RNN is the LSTM from Chapter 4, in one direction. The lecture writes one step as
\begin{align*}
i_t &= \sigma(x_t U^{i} + h_{t-1} W^{i} + b_i) \\
f_t &= \sigma(x_t U^{f} + h_{t-1} W^{f} + b_f) \\
o_t &= \sigma(x_t U^{o} + h_{t-1} W^{o} + b_o) \\
q_t &= \tanh(x_t U^{q} + h_{t-1} W^{q} + b_q) \\
p_t &= f_t * p_{t-1} + i_t * q_t \\
h_t &= o_t * \tanh(p_t).
\end{align*}
$i_t$, $f_t$, and $o_t$ are the input, forget, and output gates. $q_t$ is the candidate update. $p_t$ is the cell state. $h_t$ is the hidden vector the rest of the network uses. $U$ multiplies the current input and $W$ multiplies the previous hidden state. The same weights are used at every time step.

PyTorch's \texttt{nn.LSTM} is this recurrence. I use one layer and a hidden size of 128. For a many-to-one model the label is read from $h_T$, the hidden state at the end of the real text. Padding is not a word. If I had let the pad steps run, they would have overwritten $h_T$. I pack the batch so the recurrence stops at the last real word. We did not cover packing in class. It is only there so different lengths can share a batch.

Chapter 4 says this kind of RNN only sees one side, but it can carry information a long way. It is also slow because the steps are in order. I felt that while training. The CNN epochs were quick. The LSTM epochs were not.

I also trained a bidirectional LSTM on the output-only task. That is two of the same LSTMs, one in each direction. We did not cover it. I tried it because the lecture lists ``one side'' as the limitation. It is an extra, not the required model.

\subsection{How I picked the epoch}

I trained for at most 12 epochs. My first LSTM runs were still improving at epoch 6, so a cap of 6 was too low. After each epoch I scored the validation set. I kept the weights from the epoch with the best validation accuracy, which is the number Chapter 1 uses. If accuracy did not improve for 3 epochs, I stopped. The test set was not used for that choice. The CNN's chosen epoch on the output-only run was epoch 8 (validation accuracy 0.748). The LSTM's was epoch 7 (validation accuracy 0.623).

\subsection{Baselines from Chapter 1}

The neural nets are not the only models in the class. Chapter 1 covers Naive Bayes and logistic regression. I used both, on word counts. Each word is a feature $X_i$. The count matrix is built on the training text only, with the same 12,000-word cap.

For Naive Bayes I used multinomial counts and add-one smoothing. Chapter 1 fixes zero counts with MAP and $m$ virtual points. I set $m = 1$.

Logistic regression in class is a sigmoid on a linear score, for two classes. Slide 87 of Chapter 1 asks what the multi-class version should look like. I used one weight vector per class and a softmax, which is the same softmax as in Chapter 9. I did not add an extra penalty term. The solver did not fully converge on the instruction-only features. I say so in RQ2.

Chapter 1 calls the weights the importance of the features. I use the logistic regression weights in RQ4.

\subsection{How I score a prediction}

Accuracy is the fraction of test rows I got right. For a single class, Chapter 2 defines precision and recall from the counts $n_{ij}$. If class $j$ is the gold label, precision is the share of my predicted-$j$ rows that really are $j$, and recall is the share of true $j$ rows that I found. Then $F$ mixes those two. Chapter 2 averages $F$ over the clusters, $F = (1/r)\sum_i F_i$. I do the same average over the four models. This average is often called macro-F1. I will just call it average $F$. The count tables in the figures are the $n_{ij}$ tables, with the true model on the rows and my prediction on the columns.

\subsection{Why the instruction could have worked}

If users pick a model, or if a model was only online for part of the data collection, the instructions are not the same distribution for every label. Then the instruction predicts the model even before you see the answer. I could see a version of that in the raw files. The three FLAN subsets that Bard never answered have a stock template. Keeping them would have made the instruction useful. I removed them. After that, and after forcing each model to the same task counts, the instruction is almost useless.

There is still a small leftover. I downsampled each model separately, so the four models do not answer the exact same prompt set. That can create a tiny instruction-only lift. It is not ``the user's wording identifies the model.''

The useful signal is in the response. Chapter 7 and Chapter 8 say why that should be true. Instruction tuning and RLHF push each model toward a house style: how it starts, how long it goes, whether it hedges or itemizes. The instruction in this dataset was assigned across models. The style was not.

\section{RQ4: what the models are doing differently}
\label{sec:rq4}

Chapter 8's story is that RLHF, after instruction tuning, pushes a model toward answers humans prefer. Those answers pick up habits: longer or shorter, more hedging, more lists, more ``happy to help.'' Chapter 7 says the instruction itself changes how a model behaves, and that models do not all follow the same instruction equally. UltraFeedback adds one more instruction on top, the random principle prompt. So some of what I measure is the base model, and some of it is how that model reacted to the same extra instruction.

A few phrases show up at very different rates. I counted them on the full balanced set:

\begin{itemize}
\item ``I'd be happy'' appears in 15.6\% of Llama responses and in under 1\% of Bard and Falcon responses.
\item ``here's'' appears in 25.0\% of Llama responses and 17.8\% of GPT-4 responses, but only 1.6\% of Bard responses.
\item ``sure,'' appears in 23.5\% of Llama responses and 16.2\% of Bard responses, and in 3.6\% of Falcon responses.
\item ``as an AI'' appears in 8.8\% of Falcon responses and rarely for the others.
\item A pattern like ``80\% confidence'' appears in about 25\% of GPT-4 and Llama responses, 7.3\% of Bard, and 4.0\% of Falcon. UltraFeedback sometimes asks the model to state a confidence. GPT-4 and Llama do it. Falcon and Bard mostly do not. That is the Chapter 7 point: the same extra instruction does not land the same way on every model.
\end{itemize}

\subsection{Logistic regression weights}

Chapter 1 says the weight is the importance of the feature. On the output-only logistic regression, the largest positive weights for each class are:

\begin{itemize}
\item Bard: here, main, following, sure, variety, able.
\item Falcon: assistant (weight 13.9, the largest single weight I saw), primes, response, correct, sorry, therefore.
\item GPT-4: 95, various, remember, now, confidence, another.
\item Llama: happy, I'd, here's, 80, confidence, therefore, let's.
\end{itemize}

Those line up with the phrase counts. Llama is ``I'd be happy'' and ``here's'' and ``let's.'' Bard is ``sure.'' Falcon is ``assistant'' and ``sorry.'' The tokens 95, 80, and confidence match the confidence-score habit. I do not think ``primes'' is a deep style fact. It is probably one repeated answer. Weights can lock onto a rare word. That is a limit of reading importance off a single fit.

\subsection{K-means, from Chapter 2}

I also clustered the test-set word counts with K-means, $K = 4$, without using the labels. Normalized mutual information against the true model is 0.054. Purity is 0.355. A useless clustering of a balanced four-class problem has purity 0.25, so this is only a little better than chance. The responses do not fall into four blobs in word-count space. The supervised logistic regression still works, because it can lean on a handful of high-weight words. Unsupervised distance does not find the same split. I take that as a warning against saying the four models live in four obvious regions of bag-of-words space.

\subsection{Deleting signals and retraining}

I retrained the CNN and the LSTM after changing the response.

\begin{itemize}
\item \textbf{Strip markdown.} Fences, inline code, headers, emphasis, and bullets are removed. The words stay.
\item \textbf{Fixed length.} Every response becomes exactly 60 words, by cutting or by repeating. Length can no longer separate the classes.
\item \textbf{Strip punctuation.} Punctuation is deleted. The tokenizer already lowercases.
\item \textbf{All three.} Markdown, then punctuation, then the 60-word rule.
\end{itemize}

Markdown markers are not the CNN's main cue. Removing them costs 0.004. Forcing a common length costs the CNN 0.030. Removing punctuation costs 0.021. All three together cost 0.065, and average $F$ is still 0.680. Word choice is doing real work. That fits the logistic regression result. A linear model on counts, which barely sees order, already scores 0.732.

The LSTM does not use length the way I expected. The 60-word version is slightly better (0.602 versus 0.588). I think a fixed length makes $h_T$ easier, because every example ends after the same number of words. Punctuation matters more for the LSTM. Stripping it drops average $F$ from 0.588 to 0.518. The gates can treat a punctuation mark as a step. When those steps disappear, the final state is less informative.

One training problem: on the markdown ablation, the CNN's training loss jumped into the hundreds of thousands. Chapter 9 warns that a bad step size makes gradient descent unstable. I did not clip the gradient, because we did not cover that. I still kept the epoch with the best validation accuracy. That epoch's test average $F$ is the 0.741 in the table. I would not trust the loss curve from that run. I do trust the selected checkpoint more than a diverged one, and the score is close to the original CNN.

\section{Lessons}
\label{sec:lessons}

The result I trust most is the pair of checks. Response-only CNN accuracy is 0.745. Instruction-only accuracy is about 0.25 after I closed the Bard/FLAN hole. If those two numbers had been close, I would have been measuring the sampling scheme. Chapter 1's train/test split does not save you from that. The label can leak through $x$.

The second lesson is the CNN versus the LSTM, and it matches the Chapter 4 comparison more cleanly than I expected. The CNN sees both sides and only local context, and it wins. The one-direction LSTM sees a long context in theory and, on this data, mostly fails to use it. Reading $h_T$ only, with hidden size 128, was not enough. The bidirectional extra, which the lecture does not teach, got back to 0.717. So the ``one side'' limitation on that slide is not just a slogan. It showed up in the score.

The third lesson is Chapter 6 and Chapter 7. Holding out writing costs the CNN 0.142 in average $F$. Holding out code costs 0.076. The model is learning something that transfers, and something that does not. Llama's writing and, for the LSTM, Bard's code are the fragile cases. A detector for a new kind of task needs the held-out number.

I also learned that a linear model from Chapter 1 can beat the LSTM and almost match the CNN. The weights are readable. ``Happy,'' ``here's,'' ``assistant,'' and ``sure'' are the kind of habit Chapter 8 is about. K-means on the same counts does not recover the four models (NMI 0.054). Supervision is doing the work. The four models are not an obvious cluster.

Things I would not hide. The task labels are regular expressions. The principle prompts in UltraFeedback blur model style with a dataset choice, and the confidence-score gap is an example. The 60-word ablation repeats short answers, which is a crude way to delete length. The markdown CNN loss exploded. The LSTM test accuracy was lower than its validation accuracy. Domain test sets have a few hundred rows.

If I had more time I would try a smaller learning rate for the CNN, and I would look up gradient clipping, because that one loss curve was not acceptable. I would not switch the main LSTM to bidirectional just to get a higher score. The lecture model is the one-direction one, and the gap is part of the result.

\section{How to rerun}
\label{sec:repro}

From the repository root, with the packages in \texttt{requirements.txt}:

\begin{verbatim}
python -m src.prepare_data
python -m src.run_all
cd report && pdflatex report.tex
\end{verbatim}

\texttt{prepare\_data} downloads UltraFeedback only if the raw files are missing. The processed table used here is already in the repo. \texttt{run\_all} retrains the tables above at seed 42 on CPU. The committed \texttt{results/metrics.json} is the run this report describes.
